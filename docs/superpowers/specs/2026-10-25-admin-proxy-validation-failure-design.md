# Fixed proxy validation failure settlement

Status: approved after scoped R1/R2 builder review; R1-I1 addressed,0 open. Additional Task02.3 contract; no new task, operation, graph edge, public schema, migration or signing key.

## Problem and choice

The actual agent calls `nginx -t` before `nginx -s reload`. A conclusive validation failure currently becomes signed `unresolved` because every begun failed operation has that outcome. The DM parent cannot settle this child or run its already-permitted proxy-restore phase. A public failed status or caller-supplied failure result cannot prove containment.

Choose a fixed producer commitment for this one read-validation failure. Do not classify every failed Docker command as contained: a Docker transport error does not establish what executed. Reload failure remains unknown. Keep the existing finite graph, original root/deadline and conditional recovery policy.

## Actual command completion, not error inference

Only `feedProxy.validateAndReload` may use this producer, with the already authorized fixed proxy container and existing candidate claim. Replace its validation invocation with a fixed container shell wrapper equivalent to:

```sh
nginx -t
validation_status=$?
printf '\nOPENMAPX_NGINX_TEST_V1:%s:%s\n' "$1" "$validation_status"
exit 0
```

The agent invokes fixed argv `docker exec <existing-fixed-proxy-container> /bin/sh -c <constant-script> openmapx-nginx-test <nonce>`. Nonce is fresh128 random bits encoded base64url, generated only by this invocation. It is data in a positional argument, never interpolated shell source or a credential. No request supplies container/path/argv/script. The shell waits for nginx and exits0 only after emitting its result. Use the existing actual contained-process runner; a returned success proves normal zero Docker exec completion, no timeout/abort/spawn error/residual or uncontained local process group. The last stdout record must match this nonce exactly once and contain an integer0–255; remove the marker from diagnostics. Missing, duplicate, malformed or mismatched marker is unknown. A nonzero Docker/wrapper exit, rejected process runner, truncation, cancellation during the command or lost transport is unknown even if diagnostics look like a validation error. Test doubles that merely throw an ordinary Error cannot mint proof.

Validation code0 follows the existing candidate recheck and reload. Nonzero validation code plus normal wrapper completion is the sole known failure here. Capture/recheck the original confined candidate snapshot, including the actual mounted hardlink inode/bytes. Data-only snapshot reads may allow verified expected hardlinks; private authority records retain their existing single-link policy. An unexpected replacement/changed snapshot cannot produce this commitment. This check is settlement-only after the read and grants no new forward permission after cancellation.

## Fixed private state and producer surface

Preallocate one bounded indexed `observations` cell for this operation before effects, derived only from its validated operation key (maximum4096 bytes). Use existing family/index accounting and deletion; no completion-time allocation or separate collector. Signed origin-bearing payloads are version2/domain `openmapx-feed-proxy-validation-v2` and bind installation/origin, original execution/admission/body fingerprint, candidate ID and snapshot digest, phase and original timestamps.

Phases are `validation_pending`, `validation_failed`, `reload_started`. The first is reserved before dispatch. Failure and reload transitions are mutually exclusive and write-once under the existing private effect writer. Failure binds validation exit1–255 and a domain-separated completion digest of original execution, candidate digest, nonce and exit code. Reload-start is persisted BEFORE invoking reload; it never authorizes a failure commitment afterward. Identical repetition observes the retained proof; changed data conflicts. Missing/corrupt expected state is unknown.

The server constructs two purpose-bound internal context methods ONLY for this exact admitted operation: `commitFeedProxyValidationFailure({candidateDigest,validationExitCode,completionDigest}):Promise<void>` and `markFeedProxyReloadAttempted():Promise<void>`. They close over its nominal original authority/typed operation and private record. They are not network fields, injected user callbacks, a generic containment factory or a parsed boolean capability. The fixed Docker adapter calls commit only after verifying the actual wrapper/process/candidate observations above, immediately before throwing its ordinary runtime failure. It calls mark only after successful validation and forward/candidate checks, immediately before reload. A fixed core publisher writes/verifies this closed proof; arbitrary `OpsFailureResult` or public status cannot create one.

The signed effect receipt has one new finite private variant `feed-proxy-validation-failure` referencing the authenticated private commitment digest. Core derives `outcome:"contained", publication:"not_started"` ONLY from that exact proof for the original feedProxy operation in validation_failed phase. The failed status remains failed, not succeeded. Failure does not imply that no process ever started; it proves the validation command ended and the reload/publication phase did not start.

## Durable parent proxy recovery obligation (R1-I1)

The fixed DM proxy transaction and owned-child store own this parent obligation; a contained failed child cannot discharge it. Before the first restore/relink filesystem write, persist the original `proxy-restore` child in its existing body-first `reserved` state under current owned-row CAS. It identifies the original parent, immutable restore slot/ordinal/key/body/candidate and backup provenance. A stale/failed/ambiguous CAS authorizes zero restore writes. Pass the same live reserved continuation into the existing owned-child path; never allocate a second restore attempt.

Use one finite shared predicate `assertOwnedProxyRecoverySettled` in the server-only data execution journal policy, consumed by DM live runtime and restart. It reads complete current retained child/phase records and the original signed phase plan, not an in-memory transaction phase, caught exception or supplied success flag. Any activated/reserved/bound/attempted `proxy-restore` creates the obligation. A known failed `proxy-stage`/`proxy-commit` validation after its local candidate publication also requires the original planned restore even if cancellation prevented starting it; lack of a restore row is not successful recovery. Bind triggers and expected restore slot to the same original proxy transaction/root/targets, never a different ordinal/root or a different candidate's successful receipt. Existing reservation entries that have never been activated are not automatically attempted obligations.

The obligation is satisfied ONLY by authenticated canonical succeeded `feedProxy.validateAndReload` status `{candidateId:<that reserved restore candidate>,reloaded:true}` and matching signed committed settlement for that exact restore execution. A known contained/not_started validation failure of restore is NOT satisfaction; keep that child's authentic known outcome. Unaccepted, missing, unknown, canceled, expired, failed or mismatched restore remains pending. If no recovery was required, the predicate permits ordinary completion. Historical proof for a failed stage remains valid after legitimate restore bytes replace its candidate: verify its frozen original snapshot/commitment, not the current live candidate as if it were the old invocation.

This predicate gates ALL parent success/failure/canceled terminal SQL writes, private contained-worker completion proof, root effect settlement, release, terminal cleanup and retirement. Check the current DB child union and original signed worker evidence before each finalization/release, including the startup path for an already terminal SQL row and restart from a completed worker receipt. A pending obligation retains parent `publication:"unknown"`/recovery-required ownership, no final timestamp or successful cleanup, and the ORIGINAL target lease. Factual local-worker containment and already committed local writes may still be durably recorded, but with the unresolved recovery obligation and unknown aggregate publication; they cannot assert known parent completion or erase committed-write evidence. Do not mint a known root settlement from a completed local file-write observation while recovery is pending. Older terminal rows or inconsistent DB/private records remain fenced rather than released. Store CAS cannot erase or replace the triggering/restore child record; private completion's child digest and current records must agree.

Restart may reconcile these original child receipts and copy the same verified evidence, but never executes another restore/reload or chooses a new key/deadline. Cancel/expiry can prohibit forward restore without clearing the obligation. Only actual original successful restore evidence permits the original failed parent to settle/release truthfully; the parent still reports its original pipeline failure. Unresolved recovery is outside72h terminal retirement and remains visible for recovery.
