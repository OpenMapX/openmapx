## 2. Execution identity and time

Export from server-capable core `ops/execution-identity.ts`:

```ts

type ExecutionRef = {
  executor: ControlIssuer;

  kind: string; admittedAt: number; requestedDeadlineAt?: number;
  parent?: VerifiedParentExecution;

```

IDs use their actual producer's validator: agent `job1_…`, data-manager UUID, host CLI random UUID persisted before any effect. Keys retain `^opk1_[A-Za-z0-9_-]{16,64}$`; both fingerprints are64 lower-case hex. `operationFingerprint` is the existing `opsOperationFingerprint(operation)` (or canonical data input hash). `fingerprint` is the **execution** hash of version2, kind, body fingerprint, normalized absolute deadline and immutable parent identity, using domain-separated SHA-256 canonical JSON. Do not replace the body hash inside existing trusted-configuration HMACs or `OpsTrustedClaim.fingerprint`: retain both fields and validate their distinct roles. Admission/status/cancel/lookup and all new child records expose/use the execution fingerprint; v1 journals stay readable with explicit version1 semantics and never acquire invented parent authority. Version2 journal parsing recomputes both hashes.

All millisecond times are finite safe integers since epoch. At first admission compute `deadlineAt = min(requestedDeadlineAt ?? admittedAt + kindBudget, verifiedParent.deadlineAt ?? Infinity, admittedAt + deploymentClampedKindBudget)`. Reject an already elapsed deadline before effects. A child must supply its parent assertion and requested absolute deadline; omission on a parented call is invalid. Store `admittedAt`, requested and normalized deadline before dispatch. On a duplicate key, compare the same normalized input using **original admittedAt**, not today's clock: a changed normalized deadline/body/parent conflicts409; an exactly identical identity returns the retained operation without extending time. Missing/expired retained identity following an attempted POST is unknown, never permission to retry that mutation. Unparented supported host CLI is authenticated as host-cli and gets the same server kind/deployment clamp.

02.1 extends the strict **ops request envelope**, not arbitrary operation bodies, with optional `execution:{requestedDeadlineAt:number}`. `OpsClient.execute(operation,options)` adds `execution?:{requestedDeadlineAt:number}`, `controlAssertion?:string`, `parentAssertion?:string` to its existing operationKey/signal options; the latter two only set the fixed internal headers. Existing issuedAt/expiresAt remain short request authentication timing and never become the backend execution deadline. Version2 async admission/status/lookup/cancel all return `{admittedAt,deadlineAt,fingerprint}` with the retained identity. Sync operations also clamp runtime to remaining budget. All six existing MOTIS/proxy effect kinds in this graph are already async in `contract.ts:189–194`; preserve that durable admission. Change the existing sync data-manager `transitousLock.approve` to the durable async paired commit in§4.1; do not add a second approval command. Cancellation's existing fingerprint header carries the normalized execution fingerprint for version2. Public API SDK requests cannot inject these internal fields/headers.

02.1 retains the specified budgets: build12h, buildAll24h, Full Update48h, existing large data operations24h; later artifact jobs72h/default,7days ceiling, catalog validation72h, activation1h, advanced Overture24h, platform API job1h. A platform API job owns one absolute deadline in its DB checkpoint; each agent child is clamped to the remaining value, with no long-lived `platformConfig.apply` ancestor. API-parent assertions use the existing API bearer boundary toward agent and durable API job metadata; the agent re-attests its admitted child for any downstream delegation. The browser never supplies a trusted parent or arbitrary expanded deadline.

Keep four clocks separate: ordinary HTTP admission/read timeout15s; each observer's independently chosen `observerDeadlineAt`; retained execution `deadlineAt`; containment/settlement window30s **after** expiry/cancel. Runtime starts no new forward phase after execution expiry. The settlement window allows cancellation, process-group containment and evidence reads, not a fresh restart/promotion/rollback budget. Existing `promote.ts` recovery that grants a fresh restart budget must instead use the remaining retained deadline; if expired it records recovery-required and holds the fence. At30s unresolved containment remains pending/unknown and reconciliation continues; elapsed grace does not release ownership. HTTP close/observer expiry never calls cancellation. Execution expiry and explicit cancellation persist intent, then signal all owned children.

`OpsExecutionContext` gains readonly `execution: ExecutionRef`, `artifactLease?: BorrowedArtifactTargetLease` and trusted internal parent metadata; the server constructs them after authentication/admission and keeps them out of `capability.values`. `FixedCliOptions` retains signal/log callbacks and adds required `execution` for managed operations, plus internal `controlAssertion?: string` and `parentAssertion?:string`. The fixed runner serializes execution as bounded≤2KiB `OPENMAPX_CONTROL_EXECUTION`, checked against its signed assertion and retained spawn intent; that unsigned environment field alone grants nothing. Legacy short scheduled callers may omit execution only where their existing bounded policy is explicitly retained. ## 3. Anchored filesystem authority

### 3.1 Fixed trust material, not a generic authority service

06.1 extends the existing local Compose secret preparation with exactly three installation Ed25519 role keypairs: `ops-agent`, `data-manager`, `host-cli`. Private role keys live at `infra/docker/secrets/control-<role>.key` (0600, owner UID); public verifier bundle is `infra/docker/secrets/control-verifiers.json` (0600). No browser API can rotate/select them. Create missing keys with exclusive durable creation; never overwrite an existing key, silently regenerate after a missing verifier, or rotate while active protocol records exist. Validate key kind, installation UUID, role, owner, mode, regular-file/no-symlink/single-link and bounded size. Bundle≤4KiB contains only installation UUID and the three public keys. Preserve old records across ordinary restart; a host key rotation first settles every old record or requires explicit offline recovery.

Mount only the appropriate role key read-only at `/run/secrets/openmapx-control-role-key` and the verifier bundle read-only at `/run/secrets/openmapx-control-verifiers` in each service. Give data-manager its own0700 recovery bind `@infra:control-private/data-manager` → `/var/lib/openmapx/control-private`; the agent uses `@infra:control-private/ops-agent`. These directories are **outside** `/data` and outside the sibling's mounts. Host CLI uses fixed `infra/docker/control-private/host-cli`; fixed CLI spawned inside the agent uses the agent recovery directory and a delegated ephemeral key, not an exported role private key. The external configuration helper uses the agent private directory through its existing fixed helper mount and survives the agent process. Host/Docker administrators remain trusted. A compromised data-manager can deny shared-disk service, but its role key cannot impersonate ops-agent or widen agent per-kind policy. This added provisioning is required because same-UID/shared-data permissions alone cannot provide authenticated adoption; it is a narrow deployment cost, not a new network lock/secret service.

### 3.2 Files and records

Open the trusted local data root once by descriptor; refuse symlink root or unsafe ownership/modes. Use physical descriptor dev/inode identity so host/container aliases meet in the same directory. Under fixed `.admin-target-control/` create `locks/<serviceId>/` by exclusive mkdir and `leases/<UUID>/` for protocol state. Service IDs are canonical registered IDs≤64 characters, sorted and unique, maximum256. Never hash path spellings as lock identity. The shared namespace uses the same configured UID/GID,0700 directories,0600 regular single-link files, O_NOFOLLOW and before/after fstat/lstat checks. Persist records by fsync+atomic rename+parent-directory sync; cap a single lease ledger at128KiB, at most64 child intents, and at most256 unsettled leases. Refuse new work before its first effect if capacity is unavailable; unsettled records are never evicted. Terminal receipts remain72h and keys are never reused by the producer.

An immutable role-signed owner certificate binds `{version:1,installationId,leaseId,dataRootIdentity,lockIdentities,owner:ExecutionRef,ownerPublicKey,serviceIds,createdAt}`. Dev/inode are decimal strings, no local paths. Its ephemeral per-lease private key is stored only in the issuer's fixed private recovery directory. The mutable `LeaseOwnerRecord` is signed by that key and contains `{certificate,sequence,phase,grantDigests}`; phase is `held|cancel_pending|recovery_required|settled`. Separate `grants/<delegation-UUID>.json` records contain the parent-signed immutable grant and issuer-signed prepared/attempted transition; separate `children/<delegation-UUID>.json` records contain the recipient-signed adoption/settlement transitions. Each node has its own monotonic sequence. Child intent binds grant digest, parent node, finite phase, execution identity and target subset, plus accepted ID/settlement when available. A borrower signs only its own child record and permitted descendant grants with its certified child key; it cannot rewrite the root-signed record or needs the root private key. Root terminal/release aggregates the complete anchored grant tree rather than trusting a mutable child list supplied by a borrower. Sensitive assertions/private keys are absent from ops/API journals, argv, events and public status; private recovery files alone retain resumable assertion bytes. Public projection is only busy/conflict/unknown plus permitted operation identity.

There is one no-steal `.journal-writer` mkdir guard **per lease** for record CAS, never a global lock broker. Signed `sequence` increments under that guard; verify current directory identity, owner certificate, every held target inode and parent phase before mutating. A crashed metadata writer blocks until supervised reconciliation with all relevant writers quiescent. Never remove an unexplained nonempty or replaced lock. Save each executor's private expected certificate digest/sequence high-water mark with its durable operation receipt; stale/replaced/shared-file rollback conflicts. The ledger is protocol admission authority, tied to the real durable job through `ExecutionRef`, not a process-local cache. Before publishing a job's cancel/terminal state, its adapter first writes the corresponding ledger transition; after a crash, startup reconciles ledger↔journal before admitting new work. Terminal preparing operations may retain only the configuration-maintenance continuation (§5.4) and configuration-helper continuation (§3.5); neither is a live worker for drain accounting.

### 3.3 Exact library surface

Export from `build-artifacts/target-lease.ts` (server-only):

```ts

  inherited?: BorrowedArtifactTargetLease; signal?: AbortSignal },

```

All `Verified*` types are nominal, constructor-private values minted by the relevant fixed adapter after descriptor/signature/role/job checks; no caller boolean or cast from a request is an authorization mechanism. `VerifiedExecutionAuthority` binds the local admitted durable record and role signer. `VerifiedRecoveryAuthority` additionally proves exact durable record ownership and containment observations; a matching UUID is insufficient. `VerifiedChildSettlement` is built from authenticated status plus durable effect evidence, never arbitrary caller text. `ControlRecipient` is `"fixed-cli"|"data-manager"|"ops-agent"|"configuration-helper"`. `ControlChildPhase` is the finite phases in §3.5, not free text. `VerifiedControlPeer` comes from the fixed HTTP/CLI adapters in §3.4. These constructors live in `control-authority.ts`; service-specific adapters supply their existing typed journal/store lookup, never a generic user-pluggable authority callback.

Acquisition attempts all sorted targets under one5s budget, releasing only successfully acquired empty locks if acquisition fails before ledger publication. Once published, release checks current certificate/inodes, no unsettled intent/borrower/descendant, durable own-effect settlement and no unknown publication. A normal root writes its signed settled receipt after the effect/containment proof, then releases; its outer agent handler may still be returning, so do not require an impossible already-terminal outer journal before callback return. Every attempted child must already have its own verified settlement. The special helper alone additionally waits for its prepare parent's terminal journal before drain. `withArtifactTargetLease` does **not** unconditionally unlock in `finally`: failure/abort with an attempted child or unknown effect marks recovery-required and retains the fence. A borrower can settle its own child/node, never call root release; the library rejects forged/mixed handles. An inherited lease must contain the exact required target closure or fail before work, never acquire extra targets while borrowed. No target waits while retaining a partially acquired set beyond the shared budget.

### 3.4 Both-direction verification and admission transport

`ArtifactDelegationAssertion` is a base64url canonical signed envelope≤4096 encoded header bytes, carried in exactly one `x-openmapx-control-delegation` internal HTTP header or the fixed CLI environment variable `OPENMAPX_CONTROL_DELEGATION`. Reject duplicate raw headers, invalid encoding, extra fields and over-limit chains. Its compact fields are `{version,installationId,leaseId,ownerCertificateDigest,delegationId,grantDigest,ancestorDelegationIds,signature}`. It names only UUID/digest-derived fixed records, never paths. The referenced parent-signed grant binds parent execution, child kind/key/body+execution fingerprints, target subset, deadline, one-use delegation UUID, recipient, child public key, permitted further edges and depth. Load and verify that exact bounded grant and root certificate from the shared ledger; do not inline256 target IDs/certificates into an oversized HTTP header. No bearer/private key is inside it. The parent persists the grant and **attempted** intent before first POST/spawn, in both execution receipt and lease ledger. Signature chain length≤3; full grant nodes/targets remain within the128KiB ledger budget. Bound both optional control headers together to8192 encoded bytes.

Verification location is real admission: `apps/ops-agent/src/server.ts` for data-manager→agent; `services/data-manager/src/auth.ts` plus execution/link admission in `api.ts` for agent/CLI→data-manager; `packages/cli/src/lib/control-context.ts` for fixed child entry; existing external helper entry for the configuration continuation. Keep the data-manager bearer and the agent's distinct role token guards. Agent additionally requires the signer/peer principal to be data-manager for data-manager-origin grants. Data-manager resolves the origin role from the pinned role certificate, not its shared bearer token or a caller `role` header. CLI verifies the anchored certificate, spawn intent and own fresh execution challenge/key; the default runner removes inherited control variables from unrelated subprocesses and supplies them only to its fixed command. Never forward a parent assertion to an unrelated request or integration.

The recipient checks: configured installation/verifier, full signature chain, current immutable lock identities, current signed ledger sequence/phase, durable grant entry and parent job binding, exact child body/execution fingerprints, audience, target subset and deadline. Existing policy still authorizes operation and resources independently. HTTP recipients use their already-pinned role public key as childPublicKey. For fixed CLI/helper children the parent allocates a fresh keypair before spawn in its private recovery directory at the fixed delegation-ID-derived location; the child reads only that certified key through its fixed adapter, with no caller-selected path or key in argv/environment. The signed grant allocates a random proposed receiver execution ID using the receiver's actual job1/UUID format. Admission accepts that ID only on this authenticated internal path, checks uniqueness with key/fingerprint/parent, and otherwise creates its usual server-assigned ID; public callers cannot select another job's ID. To avoid a cross-store atomicity gap, first create the receiver's durable `pending-adoption` record with that predetermined ID and fingerprint; then under lease journal guard exclusively create the recipient-signed child record claiming that delegation UUID; then persist `adopted/ready` before any effect. A crash in either gap is fenced and reconciled; no effect occurs until both agree. Duplicate exact admission observes this one retained receiver; a different identity or second claimant conflicts. These duplicate observations are allowed after grant deadline but cannot authorize fresh effects. Borrowers can sign narrower descendants only along the enumerated edge and within the inherited deadline/target subset; they never receive the root private key. For a new grant the parent computes a requested absolute child deadline no later than its own and the recipient's advertised kind budget, retaining its expected execution fingerprint. Admission recomputes the clamp; a stricter changed deployment policy that changes the signed identity refuses before adoption rather than silently changing the grant. No second mutation is issued from the same attempted intent.

Deadline-only parents (not holding targets), notably Full Update→data execution, use `x-openmapx-parent-execution`/`OPENMAPX_PARENT_EXECUTION` with the same fixed signature/recipient/one-use/retained-attempt validation, but an execution certificate rather than a lease certificate. `attestParentExecution(authority, child)` and `verifyParentExecution(assertion, peer, retainedAttempt)` in `control-authority.ts` produce/consume `VerifiedParentExecution`. Such an assertion grants **no** target ownership; the child must acquire its own target lease. The local execution authority receipt is under the same issuer-private recovery root, keyed by operation key,≤64KiB and includes current phase/deadline/child intents. It provides the retained parent bound checked by the verifier, without a general network authority API. Signed shared execution witnesses under `.admin-target-control/executions/<issuer>/<opk>.json` expose only those safe fields; validation/CAS/crash fencing is identical to the lease ledger. API→agent uses the existing API authenticated admission plus exact retained API job identity; data-manager does not trust an unsigned API identity forwarded by a CLI.

For the API→agent edge specifically,02.1's API adapter creates a purpose-bound HMAC assertion using the existing API ops token (no fourth role key). Domain is `openmapx-api-job-parent-v1`; strict signed fields are `{version:1,apiJobId,apiOwnerVersion,parentOperationKey,parentFingerprint,parentDeadlineAt,childOperationKey,childOperationFingerprint,requestedDeadlineAt,attemptId}`. It is minted only after the corresponding API job/child-attempt checkpoint CAS; no proof or hash of user secrets enters it. `apiJobId`/owner version come from the durable DB runner, not HTTP input. Agent verifies the HMAC with its existing API token, requires resolved bearer role api, uses this retained attestation as parent deadline authority and stores its digest/attemptId/parent fields in version2 admission. Same child key with any changed bound parent conflicts. It cannot be forwarded to data-manager; agent/CLI must issue its own permitted role-signed execution witness. Cancel/restart cannot mint a replacement parent deadline for an already attempted child. This is one fixed API job attestation, not a general shared signing service.
