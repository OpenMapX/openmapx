## Defect and selected approach

Task01.1's ordinary owned-services resolver checks the actual container image ID against the current local image ID of its trusted Compose reference. Pulling the same tag changes that reference from B to E while the original running container remains B. R2 correctly requires this OLD container to remain running before guard preparation. It cannot then acquire originalContainers through the unchanged ordinary resolver. Source inspection proves this contradiction independently of the Update observer timeout in293; that timeout alone does not diagnose its runtime cause.

Preserve the ordinary resolver and every existing provenance predicate. Retain the actual OLD data-manager ownership observation in the EXISTING immutable signed normal service.pull admission, from the actual production registry claim, before the pull. Revalidate it through ordinary ownership immediately before Docker pull under the existing configuration-writer/release locks. Only the exact successful normal pull source can carry that original observation into the existing private maintenance owner witness. A private candidate/owner-scoped inspector can use that authenticated original image ID for the SAME original container while applying every other ordinary provenance predicate. It does not bless arbitrary old images, containers or tags.

Rejected alternatives: relaxing ordinary image equality changes Task01.1 for unrelated requests; repulling the old tag or using a cached-image fixture changes the real Update; writing OLD runtime facts into the already sealed candidate breaks its immutable submission. A separate ownership service/store is unnecessary because the normal admission and owner already retain authenticated observations.
