# Prepared Artifact Transfer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver T01-T04: authenticated prepared-artifact export/upload/import with bounded streaming, verified compatibility, stopped consumers, recoverable atomic publication and cleanup.

**Architecture:** Extract the existing CLI bundle contract and integrity checks into a shared server-only module, harden archive admission before extraction, and reuse that code in CLI and typed ops-agent workflows. The API brokers opaque, principal-bound stages and durable jobs; bulk bytes stream through a dedicated authenticated transport rather than JSON job envelopes or browser buffers.

**Tech Stack:** TypeScript, Node streams/filesystem, Fastify, Zod, typed ops-agent, React/MUI, generated admin SDK, Vitest; existing build records, service registry and configuration generations.

**Spec:** `docs/superpowers/specs/2026-10-23-admin-instance-management-design.md`; master `docs/superpowers/plans/2026-10-23-admin-instance-management.md`. Audit base `ef896ceae876959180116cf61ffcf643b88ebffe`.

## Global Constraints

- All product work stays in this worktree; preserve unrelated work and existing public-provider behavior. One branch/PR; no merge or production deployment.
- Use Codex provider instances only for delegated work.
- Retain `IntegrationContext`, HTTP/upstream acquisition, attribution and source policy boundaries. Community integrations remain declarative; no uploaded code execution and no browser developer toolchain.
- Docker, registry credentials, privileged host files and host data writes remain behind typed ops-agent operations. No generic command, arbitrary path or raw environment-file editor is introduced.
- Core API routes use `registerCoreRoutes`, runtime admin guards beside auth declarations, strict schemas, audit events, explicit mutation identities and appropriate rate limits. Privacy roles retain their narrower authority.
- Contracts precede generated outputs. Serialize OpenAPI/SDK generation; never hand-edit generated files. Check actual response serialization.
- Preserve configuration writer ownership, revision CAS, admission fingerprints, durable operation identities, retained results, unknown outcomes and cancellation fences. No automatic mutation retries or unproven rollback/compensation.
- Use synthetic/public data in tests and UI verification. Never print secrets, place secrets in argv or logs, or copy private operator data into artifacts.
- Stream large transfers with bounded memory, disk budgets, timeouts, cancellation and cleanup. Opaque IDs cross trust boundaries; host paths do not.
- UI controls expose availability and reasons before submission. A successful admission means queued, not applied. Failed/partial/unknown work stays visible.
- Inspect the actual rendered desktop/mobile UI locally. Do not upload screenshots to the PR, as explicitly requested.
- Complete focused checks, full local verification, relevant disposable database and runtime checks, independent review, production builds and PR CI. Report any unavailable environment gate distinctly; do not replace runtime evidence with mocked assertions.
- Read root/web `AGENTS.md`, `CONTRIBUTING.md#quality-bar` and developer API/service/integration contracts. User authorized planning only for plan authors; implementation begins after controller review. No duplicate installation, generators, builds or commits during planning.

## Review Focus

1. Malicious member names, duplicate entries, PAX/long-name headers, links, sparse files and decompression bombs cannot write outside a private stage or exceed budgets (Task 1).
2. Chunked length/digest lies, foreign-principal stage IDs and disconnects cannot finalize usable stages (Task 2).
3. A target starting, image/config revision changing, cancellation or crash around publication cannot expose a partial artifact as ready (Task 3).
4. Exporting an aliased MOTIS root, concurrently mutating a build or delivering a multi-hundred-GB file cannot expose secrets or buffer it in memory (Task 4).
5. Expiry/cleanup racing a live upload, inspection, import or download must preserve owned work and report failed cleanup honestly (Task 5).

Durable queued validation may show `validating`; once a worker claims bytes state is `claimed` with its private use/phase, and successful validation changes it to ready. Public views may label that claimed inspection as validation but never imply it is installable. Validation→ready, proven no-effect/restored→prior ready/uploaded state only while still unexpired, committed install/import→consumed, proved irrecoverable failure→failed. Unknown retains `claimed` with recovery-required evidence; neither timeout nor DELETE nor a missing live process releases it. An expired unclaimed inspection/stage returns410 and cannot be newly claimed; an already admitted claim remains pinned through authoritative settlement even after its deadline. Reconciliation requests containment at deadline, retains unknown evidence/quota, and never turns deadline expiry into settlement proof. ## Deployment transfer policy

Defaults are ceilings, not preallocation; one multi-hour country build must be practical:

- `maxUploadBytes = 1_099_511_627_776` (1 TiB); `maxExpandedBytes = 2_199_023_255_552` (2 TiB); `maxStageBytes = 4_398_046_511_104` (4 TiB aggregate reserved/occupied space); `maxEntryBytes = maxExpandedBytes`.
- `maxEntries = 250_000`; `maxManifestBytes = 67_108_864` (64 MiB); `maxPathBytes = 4096`; `maxPathDepth = 64`; extended tar header payload <=16 KiB; gzip expansion ratio <=1000 after the first 64 MiB expanded. Allow regular files/directories only, with normalized mode 0600/0700.
- `maxConcurrentArchiveJobs = 1`, `maxConcurrentTransfers = 2`, `maxConcurrentTransfersPerPrincipal = 1`, `maxRetainedStagesPerPrincipal = 4`; aggregate stream queues <=8 MiB per transfer; metadata independently bounded by manifest/entry ceilings. Never claim the whole process uses only the stream-buffer budget. The current ops-agent container has a 256m limit; controller raises its supported default to 1g for this bounded metadata work and verifies peak RSS below that limit. Deployments retaining a smaller budget must lower entry/manifest/concurrency limits or get an explicit unavailable preflight. Larger overrides require a matching declared memory budget; they cannot silently retain the 1g assumption.
- Byte-stream idle timeout 5 minutes; total upload/download budget 72 hours; stage lifetime 96 hours from creation; completed-download retention 24 hours; cleanup scan every 15 minutes. Active claims/streams have recorded absolute deadlines; reaching one initiates cancellation/containment, never ownership release. Unknown effect settlement pins stage/evidence/quota beyond that deadline until reconciliation. Expiry cannot delete a still-owned stream/claim; crash reconciliation decides state first.
- Policy ceilings are never per-operation reservations. Upload admission reserves the declared/admitted compressed byte count only, plus bounded metadata/inodes and headroom. For an unknown-length CLI stream, acquire an initial 1 GiB grant (or the remaining lower policy allowance) and extend the reservation in 1 GiB increments before writing more bytes; reject safely if extension fails. Browser File uploads declare `file.size`; actual counts must match.
- After reading and validating the bounded first-member manifest, reserve its summed expanded file sizes and directory/file inodes before extracting any payload. Count already-occupied uploaded bytes once; export reserves the calculated tar/output requirement from the source manifest. Reject manifest totals above policy ceilings. Enforce aggregate reservations/occupancy plus `max(1 GiB, 5% of this operation’s additional requiredBytes)` free headroom, current available inodes and retained rollback bytes. Same-filesystem rename does not reserve a duplicate of already-occupied old artifacts. A tiny bundle must not require 2 TiB free. Unknown capacity blocks; recheck during extraction/publication and stop safely on ENOSPC.
- Load a strict `artifactTransfer` object from the ops-agent's supported deployment policy, supplied through `OPENMAPX_ARTIFACT_TRANSFER_POLICY_FILE` at `/run/openmapx/artifact-transfer-policy.json`, mounted read-only from `@infra:artifact-transfer-policy.json`. Missing file uses documented defaults; the renderer treats this as an optional supported mount, never an arbitrary path. Only the deployment operator controls it. Positive safe integers, cross-field consistency and ceilings are validated at startup; invalid policy disables transfer with an actionable reason. Do not accept policy overrides from browser requests.
- Supported upper bounds: upload 8 TiB, expanded 16 TiB, aggregate 32 TiB, entries 1 million, manifest 256 MiB, concurrency 4, transfer deadline 7 days and stage lifetime 8 days. Stream queue ceiling stays 8 MiB. Surface effective limits before file selection; document lowering them for small hosts and raising them for large builds. Plan 08 owns any later UI for deployment policy.
