# Guarded Privacy Case Workflows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the existing guarded identity, task, decision, attachment, backup and assisted-delivery workflows in the privacy administration UI, covering P01–P06.

**Architecture:** Keep privacy decisions in the current request/identity/reauthentication services and add canonical transport schemas plus small case-bound UI components. Split touched route groups into focused plugins as needed; preserve privacy-admin authorization, request versions, durable idempotency, redaction, readiness and independent human release approvals.

**Tech Stack:** TypeScript, Fastify, Zod, Drizzle/PostgreSQL, generated API SDK, React/MUI/React Query, Vitest, existing encrypted artifact storage.

**Spec:** `docs/superpowers/specs/2026-10-23-admin-instance-management-design.md`; controller: `docs/superpowers/plans/2026-10-23-admin-instance-management.md`.

## Global Constraints

- All product work stays in this worktree; preserve unrelated work and existing
  public-provider behavior. One branch/PR; no merge or production deployment.
- Use Codex provider instances only for delegated work.
- Retain `IntegrationContext`, HTTP/upstream acquisition, attribution and source
  policy boundaries. Community integrations remain declarative; no uploaded code
  execution and no browser developer toolchain.
- Docker, registry credentials, privileged host files and host data writes remain
  behind typed ops-agent operations. No generic command, arbitrary path or raw
  environment-file editor is introduced.
- Core API routes use `registerCoreRoutes`, runtime admin guards beside auth
  declarations, strict schemas, audit events, explicit mutation identities and
  appropriate rate limits. Privacy roles retain their narrower authority.
- Contracts precede generated outputs. Serialize OpenAPI/SDK generation; never
  hand-edit generated files. Check actual response serialization.
- Preserve configuration writer ownership, revision CAS, admission fingerprints,
  durable operation identities, retained results, unknown outcomes and cancellation
  fences. No automatic mutation retries or unproven rollback/compensation.
- Use synthetic/public data in tests and UI verification. Never print secrets,
  place secrets in argv or logs, or copy private operator data into artifacts.
- Stream large transfers with bounded memory, disk budgets, timeouts, cancellation
  and cleanup. Opaque IDs cross trust boundaries; host paths do not.
- UI controls expose availability and reasons before submission. A successful
  admission means queued, not applied. Failed/partial/unknown work stays visible.
- Inspect the actual rendered desktop/mobile UI locally. Do not upload screenshots
  to the PR, as explicitly requested.
- Complete focused checks, full local verification, relevant disposable database
  and runtime checks, independent review, production builds and PR CI. Report any
  unavailable environment gate distinctly; do not replace runtime evidence with
  mocked assertions.

Planning-only boundary: baseline `ef896ceae876959180116cf61ffcf643b88ebffe`; no code, generator, build, installation, test run or commit performed. Read root/web `AGENTS.md`, API surface and Contributing quality bar; implementation reads the installed Next.js guide before adding navigation behavior.

## Review Focus

1. Selecting case B while A's read/upload/decision finishes must not put A's evidence, draft, error or reauth into B (all UI tasks, especially Tasks 1/4/6).
2. “Verified” cannot be asserted by selecting a login/email method; it needs its existing proof-producing channel, with independent representative authority (Task 1).
3. A stale version, reused mutation key with changed payload, or already-terminal request must not overwrite another caseworker's decision (Tasks 2/3/4).
4. A corrupt/unavailable backup or unreviewed supplement must not become an empty, approved source or enable generation (Tasks 4/5).
5. Reauthentication expires or identity/authority is revoked after artifact verification: zero artifact bytes leave the server and no successful-delivery event is written (Task 6).
