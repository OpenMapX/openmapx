# Durable Administrative Jobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement J01–J04: live bounded diagnostics, operation-specific multi-hour deadlines, durable cancellation/reconciliation, and Full Update completion only after its transit child and dependent builds settle.

**Architecture:** Keep the ops journal authoritative for host effects and PostgreSQL authoritative for data-manager work. Process output retention, observer lifetimes, backend cancellation and execution deadlines have distinct owners. Checkpoint each admission identity before effects, observe existing operations after disconnect/restart, and preserve failed/partial/unknown evidence rather than rerunning mutations.

**Tech Stack:** TypeScript, Node child processes/POSIX process groups, Fastify, Zod, PostgreSQL/Drizzle, Commander CLI, generated ops/data-manager/admin SDKs, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-23-admin-instance-management-design.md` and binding `docs/superpowers/specs/2026-10-23-admin-control-protocols.md`; master: `docs/superpowers/plans/2026-10-23-admin-instance-management.md`. Audit base: `ef896ceae876959180116cf61ffcf643b88ebffe`.

## Global Constraints

- All product work stays in this worktree; preserve unrelated work and existing public-provider behavior. One branch/PR; no merge or production deployment.
- Use Codex provider instances only for delegated work.
- Retain `IntegrationContext`, HTTP/upstream acquisition, attribution and source policy boundaries. Community integrations remain declarative; no uploaded code execution and no browser developer toolchain.
- Docker, registry credentials, privileged host files and host data writes remain behind typed ops-agent operations. No generic command, arbitrary path or raw environment-file editor is introduced.
- Core API routes use `registerCoreRoutes`, runtime admin guards beside auth declarations, strict schemas, audit events, explicit mutation identities and appropriate rate limits. Privacy roles retain their narrower authority.
- Contracts precede generated outputs. Serialize OpenAPI/SDK generation; never hand-edit generated files. Check actual response serialization.
- Preserve configuration writer ownership, revision CAS, admission fingerprints, durable operation identities, retained results, unknown outcomes and cancellation fences. No automatic mutation retries or unproven rollback/compensation.
- Use synthetic/public data in tests and UI verification. Never print secrets, place secrets in argv or logs, or copy private operator data into artifacts.
- Stream large transfers with bounded memory, disk budgets, timeouts, cancellation and cleanup. Opaque IDs cross trust boundaries; host paths do not.
- UI controls expose availability and reasons before submission. A successful admission means queued, not applied. Failed/partial/unknown work stays visible.
- Inspect the actual rendered desktop/mobile UI locally. Do not upload screenshots to the PR, as explicitly requested.
- Complete focused checks, full local verification, relevant disposable database and runtime checks, independent review, production builds and PR CI. Report any unavailable environment gate distinctly; do not replace runtime evidence with mocked assertions.

## Review Focus

1. A noisy process, one enormous unterminated line or split UTF-8/secret must not exhaust memory, leak a credential or kill a useful build (Task 1).
2. Lost admission/result/checkpoint responses and API/agent restarts must retain the original identity and unknown outcome, without a second mutation (Task 2).
3. Cancel before admission, during backend execution, after publication and during restart must settle from durable evidence; an observer disappearing proves none of these (Tasks 2–3).
4. Transit partial/error/interrupted/cancel-pending or a changed catalog/source revision must prevent dependent graph builds and parent success (Task 4).
5. Old handler completion racing cancellation/reconciliation cannot overwrite retained results or turn an unresolved cancel into canceled/success (Tasks 2–4).
