# Transit and Data Administration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver D01-D09: reversible sources, complete discovery, scoped sync, reviewed paired pins, supported Overture recovery, evidence-based inventory and safe feed credentials.

**Architecture:** Extend the existing desired-source overlay, data-manager pipeline, typed ops authority and server-authored operation catalogue. Persist a reviewed Transitous/GBFS generation separately from activation, bind validation to the exact inactive-slot candidate, and expose server decisions through canonical generated clients.

**Tech Stack:** TypeScript, Fastify, Zod, React/MUI, TanStack Query, Drizzle/PostgreSQL, typed ops-agent, Vitest; existing MOTIS A/B pipeline and credential vault.

**Spec:** `docs/superpowers/specs/2026-10-23-admin-instance-management-design.md`; controller: `docs/superpowers/plans/2026-10-23-admin-instance-management.md`. Audit base `ef896ceae876959180116cf61ffcf643b88ebffe`.

## Global Constraints

- All product work stays in this worktree; preserve unrelated work and existing public-provider behavior. One branch/PR; no merge or production deployment.
- Use Codex provider instances only for delegated work.
- Retain `IntegrationContext`, HTTP/upstream acquisition, attribution and source policy boundaries. Community integrations remain declarative; no uploaded code execution and no browser developer toolchain.
- Docker, registry credentials, privileged host files and host data writes remain behind typed ops-agent operations. No generic command, arbitrary path or raw environment-file editor is introduced.
- Core API routes use `registerCoreRoutes`, runtime admin guards beside auth declarations, strict schemas, audit events, explicit mutation identities and appropriate rate limits. Privacy roles retain their narrower authority.
- Contracts precede generated outputs. Serialize OpenAPI/SDK generation; never hand-edit generated files. Check actual response serialization.
- Preserve configuration writer ownership, revision CAS, admission fingerprints, durable operation identities, retained results, unknown outcomes and cancellation fences. No automatic mutation retries or unproven rollback/compensation.
- Use synthetic/public data in tests and UI verification. Never print secrets, place secrets in argv or logs, or copy private operator data into artifacts.
- Stream large transfers with bounded memory, disk budgets, timeouts, cancellation and cleanup. Opaque IDs cross trust boundaries; host paths do not.
- UI controls expose availability and reasons before submission. A successful admission means queued, not applied. Failed/partial/unknown work stays visible.
- Inspect the actual rendered desktop/mobile UI locally. Do not upload screenshots to the PR, as explicitly requested.
- Complete focused checks, full local verification, relevant disposable database and runtime checks, independent review, production builds and PR CI. Report any unavailable environment gate distinctly; do not replace runtime evidence with mocked assertions.
- Read root/web `AGENTS.md`, `CONTRIBUTING.md#quality-bar`, and developer `api-surface.md`, `service-manifest.md`, `integration-system.md`, `writing-an-integration.md`, `building-an-external-extension.md`. Resolve bundled Next.js docs before UI implementation.

## Review Focus

1. Disable followed by Enable must retain an operator source's exact URL/license; removal is a distinct confirmed action (Task 1).
2. A 501st source and a discovery duplicate must remain searchable/actionable under the installed catalog ID, including origin changes during requests (Task 2).
3. A replaced proposal, changed policy/credentials/image, interrupted activation or cron run must never approve stale or unvalidated pins (Task 3).
4. Empty output directories, multiple OSM extracts and stale build records must not imply readiness (Task 5).
5. Catalog disappearance, corrupt credentials and file/environment ownership must not erase secrets or report a successful vault save (Task 6).
